# Device Warden — 機能仕様 (MVP)

## 目的
Windows上で管理するAndroid実機・エミュレーターについて、**自分が今使ってよいか**と**どのAIが確保しているか**をひと目で判断する。人間・AI双方の衝突を減らす。

## 対象
- Windows 11 / ADB (USB・Wi-Fi) / Androidエミュレーター
- OpenCode: セッションID単位。可能ならセッションタイトル・プロジェクト・作業ディレクトリを表示
- Codex・Command Code・その他: 画面上はツール単位（例: Codex）。内部は個別のリースIDで識別
- ローカル端末専用。クラウド端末ファームやAndroid操作自体の再実装は対象外

## 画面
Windowsのタスクトレイから開ける軽量一覧。端末ごとに:
- 名前・別名・実機/エミュレーター、接続方法、ADB状態
- 最も目立つ利用可否表示
- 確保者（OpenCodeならセッションID・タイトル・プロジェクト、Codex等はツール名）
- 確保開始時刻・最終確認時刻
- 「自分が確保」「解放」「AI利用禁止」「強制解放（確認ダイアログ）」
- 最新状態の再取得

## 状態モデル
ADB接続状態、確保状態、AI利用ポリシーを独立に管理。
- connected / disconnected / unauthorized / unknown
- free / human / ai / recovery_required
- ai_allowed / ai_denied

表示ルール:
1. AI確保中かつ接続中 → **AI使用中**、自分の操作は避ける
2. 自分が確保中 → **自分が使用中**
3. 未確保かつ接続中 → **自分が使用可能**、AI利用許可ならAIも確保可能
4. 未確保かつ未接続 → **自分が使用可能（ADB未接続）**。物理的な使用可否の保証ではない
5. 確保中に接続が切れた → **接続切れ・要確認**、確保情報を維持し勝手に空きへ戻さない
6. AI利用禁止の端末 → 人間は使用可能、AIは確保不可。AI利用禁止は他状態と併記

過去に接続した端末は一覧に残し、ユーザーが非表示・削除できる。未接続でもAI確保中だった場合は「自分が使用可能」と断定しない。

## AIによる確保
- 専用CLI/APIを通じて claim / heartbeat / release / list を提供
- claimは原子的な排他処理。空き端末を自動選択でき、端末指定も可能
- AI確保中は一意なlease_idとowner(tool, session_id?, process_id?)を記録
- ADBコマンドを仲介し、指定端末を明示。端末選択は安定したIDで行い、切断・再接続時の誤割当を防ぐ
- OpenCodeプラグイン/フックからセッションIDを登録する。タイトル・プロジェクト取得失敗時もセッションIDで管理継続
- Codex等はツール名表示とし、同じツールの複数実行は内部lease_idで区別して衝突を防ぐ
- 人間による確保はGUIから操作
- リース失効/プロセス終了を検出しても突然端末を奪わない。安全確認可能な時だけ解放し、不確実なら要確認へ
- 強制解放は既存の作業中断の可能性を警告して実行・記録する
- `lease_id` は解放の資格情報として扱い、`list`・`reconfirm`・`audit` の応答には含めない。監査には短縮した参照のみ残す
- 強制解放は通常の `release` と別アクションに分離し、明示的な同意フラグを要求する。AIが使う汎用アクションからは到達できない
- ADB自体の実行失敗はBrokerの障害として扱い、端末ごとの接続が失われた証拠にはしない。リースは動かさず、次回の取得成功で状態を戻す
- ADB実行中は書き込みトランザクションを保持しない。長時間のADBが監視スレッドの更新を止めないようにする
- プラグインは `lease_id` と取得セッションの対応を保持し、他セッションのリースへの `release` / `adb` を拒否する。クライアントのタイムアウトはBroker側のADB実行時間より長くする

## 重要な制約
- adbを直接呼ぶAIや人間の操作は、仲介を通らない限り完全には検知・阻止できない。GUIに「管理外操作は保証外」と明記する
- OpenCodeのセッションIDと端末を正確に紐付けるには統合が必要。単なるプロセス監視だけで断定しない
- ADB接続中だから必ず利用可能、未接続だから物理的に利用可能、とは限らない
- セッション終了時の自動解放は実際の統合で検証するまでベストエフォート

## データ保存と安全性
- ローカルストレージに端末履歴・別名・ポリシー・リースを保存
- 端末シリアル、IP、OpenCodeのローカルパス、セッション名は公開リポジトリ/ログ/テレメトリーに載せない
- 管理APIはlocalhost限定、認証トークン等でローカル競合を抑制。不要な外部通信をしない
- 設定/履歴はgitignore。デフォルトAI利用許可方針はユーザーが切替可能

## MVP受け入れ条件
1. ADB接続/未接続の登録済み端末が正しく一覧表示される
2. 人間の確保とOpenCodeセッション確保が表示上区別される
3. Codex/Command Codeはツール名で表示される
4. 同じ端末への同時claimは一件だけ成功
5. AI利用禁止端末へAIのclaimが失敗する
6. 確保中の切断・再接続で所有者を誤認しない
7. GUIから確保・解放・強制解放が可能
8. 管理外ADB操作の限界を画面とREADMEに記載
