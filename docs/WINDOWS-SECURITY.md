# Windowsのローカルデータと権限

Device Wardenは同一PC内の協調ツールであり、同じユーザーのプロセスや管理者からの隔離境界ではありません。Brokerトークン、SQLite DB、バックアップには端末シリアル、ローカルパス、セッション情報などが含まれ得ます。公開・共有しないでください。

## 保存先とACL

既定の保存先は `%USERPROFILE%\.device-warden` です。`DEVICE_WARDEN_HOME` を指定すると別の場所を使います。**新しく作成するフォルダに限り**、Brokerは継承ACLを外し、現在のユーザー・SYSTEM・Administratorsだけにフルコントロールを与えます（`icacls` の実行に失敗しても起動は継続します）。既存フォルダのACLは、利用者のバックアップや意図的な共有を壊さないため変更しません。自動起動やBroker以外の方法で作成済みのフォルダは、下記の確認を行ってください。

移動先が共有フォルダ、別ユーザーが読める場所、バックアップ同期対象の場合は特に注意してください。Pythonの `chmod` はWindowsのACLを十分に制御しません。

確認例（自身の環境で実行。結果にはユーザー名やローカルパスが含まれるため公開しないこと）:

```powershell
icacls "$env:USERPROFILE\.device-warden"
# DEVICE_WARDEN_HOME を設定している場合
icacls "$env:DEVICE_WARDEN_HOME"
```

フォルダだけでなく `broker.token`、`warden.db`、SQLiteの一時ファイルやバックアップも確認してください。別ユーザーへアクセスを許すエントリがある場合は、そのWindows環境の管理者に相談してください。既存のACLをアプリが自動変更すると、利用者やバックアップのアクセスを壊す恐れがあるため、現時点では変更しません。

## 検証状況

開発環境の既定フォルダではSYSTEM、Administrators、現在のユーザーへの継承されたフルコントロールを確認しました。共有TEMP配下では、サンドボックス用ユーザーに継承された書き込み権限が付くことも確認しています。新規フォルダ作成時にACLを制限する処理と、既存フォルダを変更しないことをテストしていますが、**別Windowsユーザーでの実読み取り試験は未実施**です。トークン認証はlocalhostへのアクセス制御であり、トークンやDBを読める同一ユーザーのプロセスからの保護ではありません。
